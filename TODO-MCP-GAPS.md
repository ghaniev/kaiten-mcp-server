# Пробелы Kaiten MCP: что закрыто и что осталось

Собрано по живому сценарию 17.09.2026: заводил QA-карточку, переносил её на доску QA,
снимал с себя и вешал подзадачей к корневой карточке. Три шага из четырёх через MCP сделать
не удалось.

Все эндпоинты ниже **проверены живыми запросами** к `https://vibegames.kaiten.ru/api/latest`
на временных карточках, которые тут же удалялись.

---

## Закрыто в ветке `feat/card-relations-and-board-move`

### 1. Перенос карточки между досками

**Было.** `kaiten_update_card` принимал `column_id` и `lane_id`, но не `board_id`, а схема
объявлена `.strict()` — лишний ключ не игнорировался, а ронял вызов:

```
VALIDATION_ERROR: Unrecognized key(s) in object: 'board_id'
```

Карточку, заведённую не на той доске, починить было нечем. Пришлось создавать дубль на нужной
доске и удалять исходную — безвозвратное удаление там, где хватило бы PATCH.

**Проверено.** `PATCH /cards/{id}` с `board_id` + `column_id` отрабатывает, **в том числе между
пространствами** (проверял перенос из `[M1] QA` в `[M1] Flutter`, HTTP 200). Один `board_id`
без колонки даёт HTTP 400: колонка принадлежит доске, старая на новой невалидна.

**Сделано.** `board_id` добавлен в `UpdateCardSchema`, в JSON-схему инструмента и в
`UpdateCardParams`. Требование колонки вынесено в `.refine()` — ошибка приходит сразу, без
похода в API.

### 2. Связь родитель — потомок

**Было.** Инструментов нет вообще. `kaiten_get_card` умел читать связи, но создать или удалить
их было нечем. Подзадачу к зонтичной карточке не подвесить, а здесь так организована работа:
одна корневая задача и 7–8 подзадач по командам. Ссылка в описании человеку понятна, но в
прогрессе родителя такая карточка не считается.

**Проверено.** Полный круг на двух временных карточках:

| запрос | ответ |
|---|---|
| `POST /cards/{parent}/children` с телом `{"card_id": <child>}` | 200, потомок появился |
| `GET /cards/{parent}/children` | отдаёт потомка |
| `DELETE /cards/{parent}/children/{child}` | 200 |
| `GET` после удаления | `[]` |

**Сделано.** Три инструмента: `kaiten_add_card_child`, `kaiten_remove_card_child`,
`kaiten_list_card_children`. Последний отдаёт компактный список (id, title, state, owner_id,
board_id, column_id) — полная карточка тут не нужна и стоит дорого, см. пункт 4.

В описаниях явно оговорено, что `card_id` — это родитель: перепутанные местами аргументы
молча строят обратную иерархию.

### 3. Ложное обещание в описании `owner_id`

**Было.** В описании инструмента написано «Pass null to unassign», но схема null не принимала.

**Проверено, и вывод оказался другим, чем я думал сначала.** Дело не в схеме: сам Kaiten
отвечает на `PATCH` с `{"owner_id": null}` —

```
HTTP 400 {"message":"Card.owner_id should be integer"}
```

Карточка обязана иметь владельца. Снять его нельзя в принципе, только переназначить. Так что
чинить надо было не схему, а описание, которое обещало невозможное.

**Сделано.** Описание исправлено: сказано, что снять владельца нельзя и надо переназначать.
Схема оставлена строгой, на это есть тест.

---

## Осталось

### 4. `kaiten_get_card` с `format: "json"` не влезает в контекст

На обычной карточке с тремя участниками ответ — 56 тысяч символов, 754 строки. Почти весь
объём это base64-аватарки участников и владельца, повторяющиеся по нескольку раз. Markdown
такой проблемы не имеет, но из него не вытащить `board_id` и `column_id`, а они нужны, чтобы
двигать карточку. Получается, за двумя числами приходится тянуть 56 КБ и потом грепать по
сохранённому файлу.

Варианты: выкидывать `avatar_initials_url` и `avatar_uploaded_url` из json-ответа (аватарка
агенту не нужна никогда), либо добавить в markdown-вывод строку с числовыми
`board_id` / `column_id` / `lane_id`. Лучше и то и другое.

### 5. `kaiten_create_card` не умеет участников

Есть `owner_id`, но добавить `members` нельзя, а на зонтичных карточках их обычно много.

### 6. Кодировка в теле запроса

К MCP не относится, но пусть будет записано: `curl -d` с кириллицей из Git Bash на Windows
уходит в API битым, `Request body is not valid UTF-8`. Через node-клиент всё в порядке —
axios ставит `charset=utf-8` сам.
